# Database Studio benchmarks

Measures the large-file path (open, index, cached reopen, go-to-line) through the same
`FileHostService` the desktop app runs in its File Host process. Targets are in
[docs/database-studio.md](../../docs/database-studio.md), section 7.

```bash
npm run bench:db
```

| Variable       | Default                            | Meaning                                                   |
| -------------- | ---------------------------------- | --------------------------------------------------------- |
| `BENCH_SIZES`  | `100MB,500MB`                      | Comma-separated: `100MB`, `500MB`, `1GB`, `2GB`, `3GB`, … |
| `BENCH_KINDS`  | `sql,jsonl,json,csv,json-minified` | Which fixture shapes to run                               |
| `BENCH_DIR`    | `<tmp>/httpreq-bench`              | Where fixtures and `results/*.json` go                    |
| `BENCH_ASSERT` | on                                 | `0` records numbers without failing on a slower machine   |

Fixtures are generated by a streaming, seeded writer (a few MB of memory even for 3 GB), cached
in `BENCH_DIR`, and never committed. `json-minified` is one line the size of the file, to check
that nothing tries to hold a line in memory.

Read the numbers with care: after the first run the fixture is in the operating system's file
cache, so index throughput measures the scanner, not a cold disk. Use a fixture larger than the
machine's RAM, or drop the cache, for cold numbers.
